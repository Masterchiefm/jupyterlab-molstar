# AGENTS.md

Guidance for AI coding agents (and human contributors) working on this repository.

## What this is

`jupyterlab-molstar` is a **prebuilt (federated) JupyterLab 4 extension** that registers molecular
structure file types (PDB, mmCIF, BinaryCIF, GRO, PDBQT, PQR, XYZ, MOL, SDF, MOL2) with the
document registry, so double-clicking such a file in the file browser opens a full
[Mol*](https://molstar.org/) viewer tab. No kernel, no notebook code.

It is *not* a notebook widget. Existing widget libraries (ipymolstar, nglview, molview) cover the
in-notebook use case; this covers the file-browser use case.

## Repository layout

```
├── src/index.ts              # All of the plugin code (single file by design)
├── scripts/copy-vendor.js    # Copies the prebuilt Mol* viewer into labextension/static/vendor
├── jupyterlab_molstar/       # Python shim: __init__.py exposes _jupyter_labextension_paths
├── labextension/             # Build output (COMMITTED — see "Packaging model" below)
│   ├── package.json          #   generated by jupyter labextension build
│   └── static/               #   webpack bundle + vendor/molstar.js, vendor/theme/*.css
├── package.json              # JS metadata; jupyterlab.outputDir = labextension
├── tsconfig.json             # strict TypeScript
└── pyproject.toml            # hatchling packaging; wheel ships labextension as shared data
```

## Packaging model (important)

- `labextension/` **is committed to git** even though it is build output. This is deliberate:
  `pip install git+https://github.com/Masterchiefm/jupyterlab-molstar.git` must work without
  Node.js, because the wheel build (hatchling) needs those files.
- `lib/` (tsc output) is NOT committed; it is rebuilt from `src/` by the webpack step anyway.
- The ~5 MB `labextension/static/vendor/molstar.js` is the official prebuilt Mol* 5 viewer bundle.
  Do not try to import/bundle `molstar` from source in webpack — the extension intentionally loads
  it lazily via a `<script>` tag from `/lab/extensions/jupyterlab-molstar/static/vendor/`.

## Common commands

```bash
jlpm install                          # JS deps (yarn 4 via jlpm)
jlpm run build                        # tsc + jupyter labextension build + copy vendor files
pip install . --no-build-isolation    # install into current env (needs hatchling)
jupyter labextension list             # should show jupyterlab-molstar enabled OK
```

Rebuild loop: edit `src/index.ts` → `jlpm run build` → `pip install . --no-build-isolation` →
restart `jupyter lab` → hard-refresh browser (Ctrl+Shift+R).

## Environment gotchas

- `.yarnrc.yml` pins `nodeLinker: node-modules`. jlpm (yarn 4) defaults to Plug'n'Play, which
  breaks `jupyter labextension build` (it resolves `@jupyterlab/builder` via real `node_modules`).
  Do not remove that file.
- Mol* 5 keeps its prebuilt bundle at `node_modules/molstar/build/viewer/` (older docs say
  `builds/viewer/` — that path no longer exists).
- **MMTF is unsupported**: Mol* removed the MMTF parser in v5. Don't re-add it.
- Mol* `Viewer.loadStructureFromData` *appends* to the plugin state tree. Always call
  `viewer.plugin.clear()` before loading, or reloads will stack structures.
- Binary formats (`.bcif`): register the file type with `fileFormat: 'base64'`, the widget factory
  with `modelName: 'base64'`, then decode base64 → `Uint8Array` → plain `number[]` before handing
  to `loadStructureFromData` (that's what its typings accept).

## Code conventions

- TypeScript strict mode; `noUnusedLocals`; keep everything in `src/index.ts` unless the file
  genuinely needs splitting.
- `FORMATS` in `src/index.ts` is the single source of truth for supported types. To add a format:
  add an entry (name, extensions, mimeTypes, binary flag) and use a `molstarFormat` that exists in
  Mol* `BuiltInTrajectoryFormats` (mmcif, cifCore, pdb, pdbqt, pqr, gro, xyz, lammps_data, mol,
  sdf, mol2).
- Lumino lifecycle: dispose the Mol* viewer inside `Widget.dispose()`; serialize structure loads
  with a token so the latest load wins (see `MolStarPanel.setContent`).
- Theme handling swaps one `<link>` between `vendor/molstar.css` (dark) and `vendor/theme/light.css`
  based on `document.body.dataset.jpThemeLight`; a MutationObserver keeps it in sync.

## Testing (manual E2E pattern)

```bash
python3 -c "from jupyter_server.auth import passwd; print(passwd('test'))"   # make a hash
jupyter lab --no-browser --ip=0.0.0.0 --port=8888 \
  --PasswordIdentityProvider.hashed_password='$HASH' --IdentityProvider.token=''
```

Then drive headless Chromium (Playwright) with
`args=["--use-angle=swiftshader", "--enable-unsafe-swiftshader"]` so WebGL works without a GPU.
Sample files: `https://files.rcsb.org/download/1CRN.pdb` / `.cif`; BinaryCIF from
`https://models.rcsb.org/1crn.bcif`. Assert: `.jp-MolStarPanel:visible canvas` appears, no
`.jp-MolStarStatus[data-error="true"]` overlay, and screenshot pixels are diverse (not a black
canvas). Note `:visible` is a Playwright pseudo-class — it does not work inside
`page.evaluate`/`querySelector`.

## Security

Never commit credentials, tokens, or password hashes. Keep secrets out of `src/`, config files,
and test scripts.
